Rush 01

A logic puzzle and constraint satisfaction problem typically assigned during week 2. Requires backtracking, 2D array manipulation, and recursive thinking.

Overview

Rush 01 presents a grid-based logic puzzle where you must place numbers satisfying visibility or sum constraints from each row and column. The problem demands a systematic search through possible configurations using backtracking. Unlike Rush 00, this project has no single correct layout — the solution must be found through constraint propagation and search.

Key Concepts

Backtracking Constraint Checking 2D Arrays Recursion Validation Functions

Approach Discussion

The standard approach uses recursion with backtracking. Start by parsing the input to extract row and column constraints. Then recursively attempt to fill the grid cell by cell, checking constraints after each placement. If a constraint is violated, backtrack by removing the last placement and trying the next value.

Split work effectively: one partner implements the constraint checking functions while the other builds the recursive backtracking engine. Write small, testable functions for row validation and column validation independently before integrating.

Tip: Use a helper function to check if a partial solution can still lead to a valid complete solution. This prunes the search space significantly and prevents infinite recursion.

Testing Strategies

  • Test with the smallest valid grid (e.g., 4x4) before scaling up
  • Verify constraint checking functions in isolation with known inputs
  • Test with impossible configurations to confirm your program detects unsolvable cases
  • Use printf debugging to trace the backtracking steps
  • Compare output against known solutions for standard puzzle configurations

Common Pitfalls

  • Row and column validation errors — ensure you check both dimensions independently and correctly
  • Duplicate detection — failing to detect duplicate numbers in a row or column leads to invalid solutions
  • Recursion termination — missing base cases cause stack overflow or infinite loops
  • Incorrect constraint parsing — misinterpreting input format leads to wrong constraints from the start
  • Not backtracking fully — partial reset of state when backtracking corrupts the search
