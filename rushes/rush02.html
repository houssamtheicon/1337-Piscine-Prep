Rush 02

An advanced project involving dictionary-based parsing and number-to-word conversion. Typically assigned during week 3, it tests memory management, string splitting, and file I/O skills.

Overview

Rush 02 requires you to read a dictionary file mapping numbers to their word representations, then convert any given numeric input into its English (or French) textual form. This project brings together file parsing, dynamic memory allocation, and recursive decomposition of numbers into thousands, millions, and billions.

Key Concepts

Dictionaries Parsing File I/O Memory Management String Splitting

Approach Discussion

Start by designing a data structure to store dictionary entries (key-value pairs). Parse the dictionary file line by line, splitting on the delimiter. Store each entry. Then implement the conversion logic: break the number into groups of three digits (units, thousands, millions, billions) and convert each group recursively using the dictionary.

Divide the work: one partner handles dictionary parsing and storage, the other implements the recursive number conversion. Both must collaborate on the data structure design. Use malloc carefully and pair every allocation with a corresponding free.

Warning: The dictionary format can vary. Handle different delimiters, whitespace, and comment lines robustly.

Edge Cases

  • Large numbers (billions, trillions) — ensure your recursive approach scales
  • Invalid input — non-numeric strings, negative numbers, empty input
  • Missing dictionary entries — what happens if a key is not found?
  • Zero — special case in most natural language representations
  • Malformed dictionary files — missing values, duplicate keys, incorrect formatting

Common Pitfalls

  • Parsing errors — mishandling dictionary delimiters, whitespace, or newlines corrupts the entire lookup table
  • Memory leaks — failing to free dictionary entries or temporary strings causes memory exhaustion
  • Buffer overflows — writing beyond allocated memory when constructing large number strings
  • Off-by-one in number grouping — incorrect handling of digit grouping for thousands/millions/billions
  • Missing the "and" / separator logic — natural language requires proper conjunctions between groups
