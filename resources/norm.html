Norminette — The 42 Norm

The Norm is the official coding standard of 42 and 1337. Every project you submit must pass norminette checks. Understanding these rules from day one will save you countless fix sessions.

What is the Norm?

The Norm is a set of formatting and style rules that all C code must follow at 42/1337. A program called norminette checks your files automatically. If your code does not comply, your project is rejected regardless of functionality.

Important: Norminette checks are automated. There is no negotiation — either your code passes or it does not. Run norminette before every submission.

Indentation

Use 4 spaces per indentation level. Tabs are forbidden.

int     main(void)
{
    int x;

    x = 42;
    if (x > 0)
    {
        ft_putnbr(x);
    }
    return (0);
}

Line Length

Maximum line length is 80 columns (including spaces). Lines exceeding 80 characters will not pass.

Tip: Break long lines at logical points. Use descriptive but concise variable names to keep lines short.

Function Limits

  • 25 lines max per function (including the signature line)
  • 4 parameters max per function
  • 5 variables max per function (declared at the top)
// Good — within limits
int     add(int a, int b, int c, int d)
{
    int sum;
    int result;

    sum = a + b;
    result = sum + c + d;
    return (result);
}

Forbidden Constructs

These language features are not allowed in 42 C projects:

  • for loops — use while instead
  • switch / case — use if / else if
  • Ternary operator (condition ? a : b)
  • printf, malloc (unless the subject allows it), and most standard library functions
  • Global variables (except when explicitly allowed)
  • Functions from external libraries beyond write, malloc, free, and a few others

Zero tolerance: Using for, switch, or ternary will result in an automatic 0 on the project.

Comments Style

Only /* */ style comments are allowed. The // style comments are forbidden. Comments must not contain inappropriate content.

/* This is allowed */
int     x = 42;

// This is forbidden

File Structure

Each .c file must contain the 42 standard header at the top. Functions should be ordered logically, with related functions grouped together. Separate function implementations with a single blank line.

The 42 Header

Every file must start with the 42 header. You can insert it automatically in Vim with :Stdheader or in VS Code with the 42 header extension.

/* ************************************************************************** */
/*                                                                            */
/*                                                        :::      ::::::::   */
/*   filename.c                                         :+:      :+:    :+:   */
/*                                                    +:+ +:+         +:+     */
/*   By: your_login <your_login@student.1337.ma>    +#+  +:+       +#+        */
/*                                                +#+#+#+#+#+   +#+           */
/*   Created: YYYY/MM/DD HH:MM:SS by your_login       #+#    #+#             */
/*   Updated: YYYY/MM/DD HH:MM:SS by your_login      ###   ########.fr       */
/*                                                                            */
/* ************************************************************************** */

Common Violations

  • Trailing whitespace or spaces at the end of lines
  • Missing blank lines between functions
  • Variable declarations not at the top of the function
  • Multiple assignments on one line
  • Incorrect spacing around operators and parentheses
  • Missing or extra empty lines at end of file
  • Function name too long (causes line length violations when called)

Running Norminette

To check your code, run:

norminette your_file.c
norminette *.c           # Check all C files in directory
norminette -R CheckForbiddenSourceHeader your_file.c

Run norminette before every submission. Fix all errors before pushing. A project that fails norminette gets an automatic 0.
