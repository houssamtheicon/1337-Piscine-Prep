C03 — String Comparison & Memory

C03 focuses on string comparison and concatenation functions. You will implement ft_strcmp, ft_strcat, ft_strstr, and the size-bounded ft_strlcat. Understanding the return value semantics of these functions is critical for avoiding bugs.

Concepts

String Compare (strcmp) String Compare (strncmp) String Concatenate (strcat) String Concatenate (strncat) Memory (strlcat/seglen)

Common Pitfalls

  • Return value semantics: strcmp returns 0 when strings are equal, not 1. Many beginners write if (ft_strcmp(a, b)) thinking it checks equality — it checks inequality.
  • Buffer sizes in strlcat: ft_strlcat takes the full buffer size including the null terminator. The return value is the total length it tried to create.
  • Overlapping memory: strcat assumes no overlap between source and destination. Overlapping leads to undefined behaviour.
  • Null pointer inputs: The standard functions crash on NULL. Decide whether your implementation should handle it gracefully.

Peer-Eval Reminders

Check these during evaluation: Does ft_strcmp return the correct difference for unequal strings? Does ft_strstr return NULL when the substring is not found? Does ft_strlcat handle the case where destination is already full? Are edge cases tested (empty strings, n=0)?
