C 07 — Memory Allocation

C 07 introduces dynamic memory allocation. You will learn to use malloc and free to manage heap memory, duplicate strings, create ranges, join strings, convert number bases, and split strings — all while avoiding leaks and handling allocation failures.

Concepts Covered

malloc free Memory Allocation String Duplication Dynamic Arrays Memory Management

Exercises

0/6 (0%)
  • ex00: ft_strdup
    Duplicate a string by allocating new memory and copying the content
  • ex01: ft_range
    Return an array of ints from min to max (inclusive-exclusive)
  • ex02: ft_ultimate_range
    Like ft_range but returns the size and uses a pointer-to-pointer
  • ex03: ft_strjoin
    Concatenate an array of strings with a separator into a single allocated string
  • ex04: ft_convert_base
    Convert a number from one base string to another, returning an allocated string
  • ex05: ft_split
    Split a string by a charset into an allocated NULL-terminated array of strings

Compile & Test

# Compile all exercises
gcc -Wall -Wextra -Werror -o test_ex00 ex00/ft_strdup.c main.c
gcc -Wall -Wextra -Werror -o test_ex01 ex01/ft_range.c main.c
# Test with valgrind for memory leaks
valgrind --leak-check=full ./test_ex00

Common Pitfalls

  • Memory leaks: Every malloc must eventually be matched with a free. Always free allocated memory when done.
  • Null check after malloc: Always check if malloc returned NULL. If it fails, return an error indicator or NULL.
  • Forgetting free: In functions like ft_strjoin, intermediate allocations must be freed to avoid leaks.
  • Dangling pointers: After freeing a pointer, set it to NULL to avoid using freed memory.
  • Buffer overflow in strjoin: Calculate total length precisely, including separators and null terminator.
  • NULL parameter handling: Decide how your function behaves when passed NULL arguments and document it.

Peer Evaluation Tip: When evaluating C 07 exercises, always check for malloc return values, proper null termination of strings, and run valgrind to confirm no memory leaks. Pay special attention to edge cases: empty strings, zero-length ranges, and invalid base strings.
