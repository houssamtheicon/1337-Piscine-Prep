C 10 — File Descriptors & I/O

C 10 covers low-level file I/O using system calls: open, read, write, close. You will reimplement standard Unix utilities like cat, tail, and hexdump, and learn to work with file descriptors, error handling via errno, and buffered reads.

Concepts Covered

File Descriptors open/read/write close Standard Streams (stdin/stdout/stderr) errno

Exercises

0/7 (0%)
  • ex00: display_file
    Display the contents of a file using read/write (basic cat)
  • ex01: cat (ft_cat)
    Implement cat with multiple file support and stdin reading
  • ex02: tail
    Display the last N lines of a file (like tail -c)
  • ex03: hexdump
    Display file contents in hexadecimal format
  • ex04: ft_putchar_fd
    Write a character to a given file descriptor
  • ex05: ft_putstr_fd
    Write a string to a given file descriptor
  • ex06: ft_putnbr_fd
    Write an integer to a given file descriptor

Compile & Test

# Test display_file
gcc -Wall -Wextra -Werror -o display_file ex00/display_file.c
./display_file test.txt

# Test ft_cat
gcc -Wall -Wextra -Werror -o ft_cat ex01/ft_cat.c
./ft_cat file1.txt file2.txt
echo "hello" | ./ft_cat

# Test tail
gcc -Wall -Wextra -Werror -o ft_tail ex02/ft_tail.c
./ft_tail -c 10 test.txt

# Test hexdump
gcc -Wall -Wextra -Werror -o ft_hexdump ex03/ft_hexdump.c
./ft_hexdump test.txt

Common Pitfalls

  • File descriptor leaks: Every open() must have a matching close(). Forgetting to close can exhaust system file limits.
  • Error handling: Check open() return value; it returns -1 on failure. Use errno or strerror for meaningful messages.
  • BUFFER_SIZE: Define a reasonable buffer size (e.g., 4096) for read(). Too small is slow; too large wastes memory.
  • Binary files: read() works on binary data. Do not treat binary data as null-terminated strings.
  • Edge cases with large files: Ensure your tail/hexdump implementations handle files larger than available RAM.

Peer Evaluation Tip: Test with empty files, non-existent files (check error messages), binary files, and stdin input. Verify that ft_cat reads from stdin when no filename is given. Check that display_file handles multiple files correctly.
